01 / PROTOCOL

x402 的作用：把付款变成 HTTP 的一部分

当 Agent 第一次遇到陌生 API，x402 让它无需开户、签订阅或管理 API Key，即可获得报价、签名授权并付费调用。

01 REQUESTAgent 请求资源

API、MCP Tool、数据、算力或内容。

02 QUOTEHTTP 402 报价

返回价格、资产、网络和收款地址。

03 AUTHORIZE本地签名

Agent 在预算策略内生成支付授权。

04 SETTLEFacilitator 结算

验证签名并在 Base、Solana 等网络执行。

05 DELIVER交付资源

服务端返回 200 及可验证的结算回执。

02 / INITIATORS

谁发起、谁治理、谁提供产业接口

投资上要区分“协议的创建者”、“基金会共同发起方”和“成员/生态合作方”，三者不等价。

Protocol creator · 2025

Coinbase

Coinbase Developer Platform 于 2025 年 5 月发布 x402。公开发布作者为 Erik Reppel、Nemil Dalal、Dan Kim；Coinbase 同时提供了早期 Facilitator 和 Base/USDC 默认路径。

Foundation co-founder

Cloudflare

与 Coinbase 共同发起 x402 Foundation，将支付嵌入 Workers 和 Agent 边缘运行环境；其价值在于把协议带入互联网分发层。

Neutral governance · 2026

Linux Foundation

2026 年 7 月完成 Coinbase 的协议捐赠并启动中立治理。这降低了单一厂商锁定，但也意味着“x402 采用”不必然全部回流 Coinbase。

40 FOUNDING MEMBERS · Premier 成员包括 Adyen、AWS、American Express、Circle、Cloudflare、Coinbase、Fiserv、Google、Mastercard、Shopify、Solana Foundation、Stripe、Visa 等。投资含义：标准联盟很强，但成员资格不等于已产生经济收入。

04 / INVESTMENT

投资研究不应把“协议使用”直接翻译成“代币价值”

x402 本身无原生代币，价值可能被稳定币发行方、低成本链、Facilitator、钱包、服务目录和真正有付费需求的 Agent 应用分享。

THESIS 01

最清晰的受益者是稳定币与结算网络

如果 Agent 微支付增长，USDC 流通和 Base/Solana 使用受益最直接；但 Facilitator 代付 gas 会让交易笔数失真。

THESIS 02

分发和风控层可能比协议更有定价权

掌握 Agent 钱包、预算、身份、路由与服务发现的环节，能决定“谁被调用”，这比结算格式更接近护城河。

THESIS 03

真正的 PMF 优先出现在数字资源

模型推理、搜索、链上数据、爬虫和动态算力具备即时交付、低客单价、爆发调用的完美结构。

信号我们要看什么投资含义状态
真实付费需求命名服务收入、非关联 payer、复购率决定协议是否越过补贴期待证明
商户端产品化退款、税务、身份、动态计费决定能否从 API 扩展到现实商业早期
多轨互操作USDC、卡、法币、批量结算降低钱包与加密门槛加速
流量去集中前10服务/前3 Facilitator 份额降低单一运营者制造增长的风险高集中
